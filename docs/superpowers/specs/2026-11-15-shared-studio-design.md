# 小鸿雁：无需登录的共享工作室

日期：2026-11-15（日本时间）。状态：待用户审阅；尚未接入云服务、修改产品代码或发布同步版本。

## 用户决定与目标

- 保留当前生成器网址、模板、背景、字体调整及 PNG 保存方式。
- 一个人编辑后，其他人打开相同网址可以看到最新设计并继续修改。
- 使用同一个公开网址，无账号、密码或专属编辑链接；任何访问者都可读写。
- 可以退回当前各浏览器独立保存的版本，并在回退前导出云端最新设计。
- 价目表内容结构重设计不在本次范围内。

## 方案比较

1. 现有本地保存与续编链接：无需云服务，但只是快照转移，无法满足自动共享。
2. GitHub Pages + Supabase 数据库及素材存储：保留原网址，支持持久共享、条件写入及更新订阅。推荐实施方案；用户已同意继续确定方案，但尚无服务账号，正式接入前需创建项目。
3. 自建服务器：也能实现，但需额外部署、运维，不适合当前小工具。

以下为实施建议，需用户确认。Supabase 使用免费额度起步，实际额度、休眠与费用以创建时的服务条款为准；不承诺无限制免费或始终在线，不自动升级付费服务。

## 共享边界与本地状态

共享设计列表、每个设计的全部物料内容及排版设置，以及设计使用的上传背景、Logo、活动照片、二维码。六张内置背景继续随网站托管，以稳定 ID 引用。

当前选中的设计、缩放比例、当前编辑标签页保留在各自设备；不会因别人切换页面而跳转。渲染及导出依旧在本机完成，无需服务器生成图片。

本地模式继续存在。未配置云服务时沿用目前行为；共享模式使用独立本地缓存键，不覆盖原来的本地项目记录。配置通过构建变量指定，不在代码中放管理密钥。

## 首次迁移

共享库为空时展示明确的初始化入口，不由每个浏览器自动上传默认演示数据。选定一个浏览器中的现有设计，先导出完整备份，再有意识地上传为初始共享项目。

其他浏览器原本的记录继续保留，可选择导入为新共享设计；按新 ID 追加，不用旧本地内容覆盖已有共享项目。素材先上传成功，再提交引用它们的设计，避免其他人看到缺失图片。

## 保存与同步

- 输入立即留在本机草稿中，暂停输入约 800ms 后提交云端；提供立即保存。
- 显示正在同步、已同步、未同步或冲突。仅服务器确认后显示已同步。
- 打开时读取共享库；订阅更新，并在重新联网、页面回到前台时重新核对。订阅失败时采用低频轮询，不假装处于实时连接。
- 每份设计有服务端版本号。写入必须在数据库事务中校验旧版本，再递增版本号及写入历史记录；避免先读后写的竞争。
- 自己没有待保存修改时直接更新预览；自己有待保存修改时保留本机草稿，提示冲突，让用户选择采用云端版本或另存一份自己的设计。不静默覆盖远端，也不丢弃本机草稿。
- 断网时继续编辑、导出及备份，提示尚未同步；重新连接后仍需核对版本，不能用旧缓存自动覆盖最新共享数据。
- 并发创建、重命名、恢复及删除也需校验版本。其他人删除了正在编辑的设计时保留本机草稿，允许另存新项目。

## 云端数据与公开访问

建议使用 designs（数据、版本、删除标记）、design_revisions（完整版本快照）、assets（元数据与文件路径）。由数据库函数执行设计变更，前端不能直接修改历史表；每次成功保存保留修改前版本，历史按每份设计最近 30 版起步。删除为软删除，恢复也创建新版本。历史清理在服务端执行，并保留删除前的可恢复记录。

匿名访问只开放这一个工作室所需的读取和受约束的变更函数，以及限定素材目录的图片上传与读取。服务端校验结构、版本号、素材引用及输入上限；Storage 限制 JPG/PNG/WebP 和单张 20MB，保留客户端原有像素校验。初期不自动物理清理素材，避免删掉历史版本仍在引用的图片。

公开模式是用户明确选择：访问者具有相同编辑能力，不能识别修改者，也无法阻止知道网址的人恶意修改。历史恢复减少误操作损失，不构成权限隔离。客户端只能使用 Supabase 的公开项目 URL 与 publishable/anon key；service_role、数据库密码及管理令牌禁止写入仓库、网页或聊天。
